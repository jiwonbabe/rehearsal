# Rehearsal — spec (hackathon scope, 48 h)

One sentence: a brand owner picks a marketing direction for the month; the engine runs
every variant of it through 20 bad months on the brand's own numbers; the owner commits to
the plan that held up; next month the engine learns from what actually happened.

Everything below is fixed. Things not listed here are out of scope (see § Cut).

## 1. Data contract — `data/brand.json`

One brand, 52 weeks, weekly rows. Generated by `data/synthetic.py` (seeded). Shape:

```json
{
  "brand": {"name": "BND US (demo)", "synthetic": true, "market": "US",
            "target": {"gender": "women", "age": "25-34", "price_band": "80-200"},
            "avg_price_usd": 120, "product_cost_usd": 45, "goal_orders_per_month": 45,
            "budget_usd_per_month": 400},
  "weeks": [
    {"week": "2025-11-03",
     "posts": {"on_hand": 2, "close_up": 1, "flat_lay": 1, "on_neck": 0},
     "engagement": {"on_hand": 410, "close_up": 180, "flat_lay": 120, "on_neck": 0},
     "followers": 4120,
     "creators_seeded": 0, "creators_posted": 0, "creator_engagement": 0,
     "ads_usd": 0, "ad_engagement": 0,
     "promo_discount": 0.0,
     "orders": 9, "spend_usd": 0}
  ]
}
```

Rules for the generator: engagement per post by type is stable with noise (on_hand highest);
two promo weeks in the year with a ×1.8–2.2 order spike; one month (October 2026) where
`creators_seeded=4, creators_posted=1`; ads in ~10 weeks with a known CPM-like ratio;
followers grow slowly. Seed fixed (`seed=7`). The last 4 weeks are October 2026.

## 2. Plan — the only thing the planner may emit

```json
{"plan_id": "ads-012", "direction": "pay_for_reach",
 "posts_per_week": 4,
 "post_mix": {"on_hand": 0.5, "close_up": 0.3, "flat_lay": 0.2, "on_neck": 0.0},
 "creator_count": 0,
 "ads_usd": 180,
 "promo_week": null, "promo_discount": 0.0}
```

No other fields. No numbers for orders, reach, or revenue. Horizon = 4 weeks.

## 3. Direction — what Spark returns (call 1)

```json
{"directions": [
  {"id": "pay_for_reach", "title": "Pay for reach on what already works",
   "plain": "Put ad money behind your two best on-hand posts...",
   "why_for_you": "Your October ads landed inside range; this group responds to worn shots.",
   "you_would_do": "Pick 2 posts, set a daily cap, keep posting 3-4x/week.",
   "rank": 1, "caution": null,
   "ranges": {"posts_per_week": [3, 5], "creator_count": [0, 0], "ads_usd": [120, 260],
              "promo_week": [null], "promo_discount": [0, 0],
              "post_mix": {"on_hand": [0.4, 0.6], "close_up": [0.2, 0.4], "flat_lay": [0.1, 0.3], "on_neck": [0, 0.1]}}}
]}
```

3 or 4 directions. Input to Spark: target profile + a short data summary that the engine
produces (`engine/summary.py`): per-type engagement per post, seed post rate, last month vs
range, promo history. Spark sees numbers only as context; it returns text and ranges.

## 4. Shock — what the adversary returns (call 2)

Catalog (code, fixed): `reach_drop`, `creator_noshow`, `competitor_sale`, `cpm_spike`,
`shipping_delay`, `viral_post`, `promo_underestimate`. Each has a fixed effect in
`engine/shocks.py` and a prior probability from the data (noshow prior = 1 − seed post rate).
Spark returns, per direction, 20 combos of 1–3 catalog codes with a one-line reason each:

```json
{"shocks": [{"codes": ["reach_drop", "creator_noshow"], "why": "kills seeding plans first"}]}
```

If the call fails, code falls back to a fixed list of 20 combos. Codes outside the catalog
are dropped.

## 5. Engine — `engine/` (Go; `reference/engine` is the Python original and the golden source)

- `calibrate(brand)` → rates: `eng_per_post[type]`, `order_per_engagement` (non-promo weeks),
  `promo_multiplier`, `seed_post_rate`, `eng_per_creator_post`, `ad_eng_per_usd`.
- `run_plan(plan, rates, brand, shocks=[], weeks=4)` → per-week `{engagement, orders, spend_usd}`
  and totals. Funnel per week: engagement = organic + creator + ads; orders = engagement ×
  order_per_engagement × promo_mult; spend = ads + creators × product_cost + orders × price ×
  discount. Shocks modify rates or weeks as defined in `engine/shocks.py`.
- `survived(result, brand)` → True if total orders ≥ goal and cumulative spend never exceeds
  budget before week 3.
- `sample_variants(direction, n=60, seed=7)` → plans inside the ranges.
- `stress(plans, shock_combos, rates, brand)` → matrix `[plan][combo] → {orders, spend, survived}`.
- `verdict(matrix)` → per direction the plan with most survivals (tie: lower spend); also the
  no-spend baseline.
- `flip(top_a, top_b, rates, brand, param)` → threshold value of `param` (default
  `seed_post_rate`) where the ranking of A and B swaps, by sweeping 0.3–1.0 in 0.02 steps.
- `backtest(brand, rates)` → replay the last 13 weeks' actual inputs through `run_plan`
  logic and return per-week engine vs actual orders, median abs % error, weeks inside range.
  (Range = engine ± 20%.)
- `review(brand, committed_plan, actual_month, rates)` → which rate was off, new rates
  (blend: new = 0.7 × old + 0.3 × observed), and a one-sentence diagnosis built from a
  template, not from a model.

## 6. UI — 5 screens, Go net/http + one HTML file per screen in `web/`, no framework

0 Setup (target profile pre-filled from `brand.target`, editable; budget; goal; backtest card)
1 Directions (cards from Spark cache; pick 1–2; second month shows "what last month taught")
2 Simulate (matrix; JSON patch of one plan; shock list)
3 Verdict (best per direction + baseline; flip assumption; to-do template on commit)
4 Review (October actual vs range; diagnosis; rate changes; button → Directions re-ranked)

Every page: top badge "Demo brand · synthetic data". The Review → Directions re-run must show
a visible ranking change (the synthetic October no-show makes seeding drop below ads).

## 7. Build order

Done: `data/synthetic.py` → `data/brand.json`; Go `engine/` matching `reference/fixtures`
(`go test ./...` green); `spark/client.go`; `cmd/server` with /api/brand, rates, backtest, summary.
1. Spark: call Directions once and Adversary per direction, commit the cache files; add
`spark/validate.go` (ranges inside budget, codes in catalog, else defaults). 2. `/api/directions`,
`/api/stress`, `/api/review` in `cmd/server`. 3. Web screens 0–2. 4. Screens 3–4 with the loop
(Review → Directions re-ranked with new rates). 5. README, DEMO.md, record.
