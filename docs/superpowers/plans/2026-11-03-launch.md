# Launch: brand-specific playbooks and one-click execution — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every direction carries a playbook written for this brand, and the committed plan becomes a paused Meta ads campaign, a creator seeding kit, and a downloadable posting calendar.

**Architecture:** One new Spark call per direction (`playbook-<id>`) adds text only; the engine gains `RunLaunch` (mirrored in Python with a fixture) for every number on the Launch screen; `cmd/server/launch.go` wires both and holds the Meta Marketing API adapter (paused objects only, dry-run without credentials) and the `.ics` writer. Existing directions/adversary/check caches are untouched.

**Tech Stack:** Go 1.22 stdlib, Python 3 reference, vanilla HTML/JS.

**Spec:** `docs/superpowers/specs/2026-11-03-launch-design.md`

## Global Constraints

- Go 1.22, stdlib only. `gofmt -l . && go vet ./... && go test -count=1 ./...` clean before every commit. Never pipe `go test` into `tail`.
- Models propose text/labels; `engine/` computes every number. Spark playbook strings containing `$<digit>` or `<digit> orders|revenue|%` are dropped by validation.
- Deterministic engine: no `time.Now()`; dates derive from `brand.Weeks[last].Week`.
- Oracle isolation: `spark/` never imports `rehearsal/engine`; `engine/` never imports `spark`; only `cmd/*` import both.
- Engine formulas live in BOTH `engine/` and `reference/engine/`; regenerate with `python3 reference/dump_fixtures.py`; never hand-edit a fixture.
- The words "forecast" and "prediction" never appear in `web/` (enforced by `cmd/server/web_test.go`). Every page shows the `Demo brand · synthetic data` badge (via `renderHeader`).
- Server never calls Spark live (`main()` unsets `MUSE_API_KEY`). Only `cmd/sparkcache` calls live: `MUSE_API_KEY=... go run ./cmd/sparkcache`.
- Meta ads objects are always created with `status=PAUSED`. Credentials come from `META_AD_ACCOUNT_ID` + `META_ACCESS_TOKEN` env; never written to files or commits.
- Commit after each task, one line, ending with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. A plan with `creator_count` 0 and `ads_usd` 0 (just_post): Launch must still render the calendar and show no ads/creator cards without erroring (Task 3 test `TestLaunchJustPost`).
2. `posts_per_week` 3.5 with mix that does not sum to 1 in floating point: posts per week must sum to `round(posts_per_week)` (Task 2 test `TestLaunchPostsSumToWeekly`).
3. Spark returns 3 or 5 weeks, or a playbook string with "$120": validation pads/truncates to 4 and drops the string (Task 1 test `TestValidatePlaybook`).
4. No Meta credentials: the ads button must return the request and `sent:false`, never 500 (Task 3 test `TestLaunchAdsDryRun`).
5. Graph API returns an error body: the handler returns 502 with the body text, and nothing claims "sent" (Task 3 test `TestLaunchAdsLiveError`).

- `func icsFor(spec engine.LaunchSpec, title string) string` — `BEGIN:VCALENDAR\r\nVERSION:2.0\r\nPRODID:-//Rehearsal//EN\r\n`, one all-day `VEVENT` per calendar week with `DTSTART;VALUE=DATE:YYYYMMDD`, `SUMMARY:Week N · post 3× (2 on hand, 1 close up) · ship 4 pieces`, `UID:rehearsal-week-N@<start>`, plus one `VEVENT` on `start_date` `SUMMARY:Ads start · $<daily>/day paused campaign` when `AdsUsd > 0`.
