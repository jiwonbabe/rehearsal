# Meta evidence, channel reasoning, Korean — design

Date: 2026-11-03 (afternoon). Deadline Nov 4, 6pm PT. Scope chosen by Claude after the
brainstorm; the user asked for "the most that fits in a day". Ordered by demo impact; the
tail gets cut first.

## Intent

The directions still read like advice anyone could give. Two fixes:

1. **Ground the advice in the brand's own Meta data.** Instagram and Threads insights
   (which formats reach, which post types get saved, who the followers are), hashtag top
   posts and peer brands for the category, and Meta's reach estimate for the target. The
   engine turns that into evidence numbers; Spark reasons over the evidence plus a small
   table of sourced public statistics and says, per channel, lead / support / skip, why
   (quoting evidence numbers only), the industry reasoning (labelled as Spark's judgment),
   and how to post there. Playbooks are regenerated with the channel verdicts so week plans
   name formats and channels.
2. **Korean.** A header toggle EN / 한국어, default English (the demo is in English).
   Static copy from a dictionary; Spark text translated by Spark once per cache file and
   served as an EN→KO map, so numbers and rankings are identical in both languages.

Demo data is mock JSON shaped like the Graph API responses; the live seam reads the same
shapes from Instagram Graph API / Threads API / Marketing API when a token is present.

## Goals

- A **Channels** card on Directions: for this brand, each channel with a verdict chip, one
  "from your data" line (badge: *Your Instagram · 90 days*), one "public data" line with a
  source link when a sourced statistic applies, one "Spark reasoning" line (badge), and a
  "how to post" line.
- Setup Step 1 gains "Connect Instagram (demo data)" that loads the mock and shows audience
  numbers (top age band share, women share, top city) next to the screenshot read.
- Launch: Ads card shows Meta's reach estimate for the target; Creators card lists suggested
  creators from the mock business_discovery results with fit labels.
- Korean toggle on every page; the badge reads "데모 브랜드 · 합성 데이터" in Korean.

## Non-goals

- Orders by channel (needs the shop). Link taps are the conversion proxy and are labelled so.
- Stress-testing channels in the engine. Channel verdicts are labelled "reasoned, not
  stress-tested".
- Live calls during the demo. App Review. Automatic refresh of public statistics.

## Anti-goals

- A number on screen that Spark wrote. `why_data` lines are validated: every number in
  them must appear in the evidence or the statistics table (same rule as the check line).
- A public statistic without a source URL and year.
- Mixing languages: in Korean mode, no English sentence is left except handles, hashtags,
  platform names and the brand name.

## How it is built

### Mock Meta data (`data/meta/bnd.jewelry/`, generated by `data/meta_mock.py`, seed 7)

Files shaped like the API responses, `source: "mock"` inside each:
- `account.json`: `follower_demographics` by age band and gender, top cities with shares,
  `followers_count`.
- `media.json`: 24 posts over 90 days: `id, timestamp, media_product_type` (FEED|REELS|
  STORY), `post_type` (on_hand|close_up|flat_lay|on_neck; "labelled by Spark vision" in
  live), `insights`: reach, views, saved, shares, likes, comments, link_taps.
- `threads.json`: 10 Threads posts: views, likes, replies, reposts.
- `hashtags.json`: for `#데일리주얼리` and `#everydaygoldjewelry`, 30 top media each with
  `post_type`, like_count, comments_count.
- `peers.json`: 3 peer brands from business_discovery: username, followers_count,
  media_count, 12 recent posts with post_type and like_count.
- `creators.json`: 6 creator accounts from business_discovery for the brief's search terms:
  username, followers_count, biography, 6 recent posts with post_type and like_count.
- `reach_estimate.json`: Marketing API delivery_estimate for the target by placement:
  instagram_reels, instagram_feed, instagram_stories, facebook_feed → estimate_dau,
  estimate_mau.

### Engine: `RunEvidence(m MetaData) Evidence` (Go + Python + fixture)

- `audience`: `top_age`, `top_age_share`, `women_share`, `top_city`, `top_city_share`
  (shares 2dp).
- `formats[]`: for feed, reels, stories, threads: `posts`, `avg_reach` (threads: avg views),
  `avg_saves` (threads: avg replies), `link_taps_per_post`, `reach_vs_feed` (2dp; feed=1).
- `post_types[]`: for feed+reels media, per post type: `posts`, `avg_reach`, `avg_saves`;
  `best_type` by avg_saves.
- `category`: per hashtag: `share_by_type` (2dp), `avg_likes_by_type`; `peers[]`:
  username, followers, `post_mix` shares, `avg_likes`.
- `creators[]`: username, followers_band (small <10k, mid <100k, large), `engagement_rate`
  = avg likes / followers (3dp), `post_mix`.
- `reach`: pass-through of the estimate (Meta's numbers, labelled "Meta estimate").
- All averages rounded to whole numbers; shares 2dp.

### Public statistics (`data/platform_stats.json`)

Hand-written rows with `market, age_band, platform, share, source, url, year`, only numbers
found in the sources checked on Nov 3, 2026 (Pew 2025 US survey; KT Nasmedia 2026 NPR
target infographics). Few rows; each row carries its source. Served with the evidence.

### Spark role 7: channels (`prompts/channels.md`, cache `channels-<handle>.json`)

Input: evidence JSON, profile read, statistics rows for the market, brand basics. Output:
```
{"channels": [{"channel": "instagram_reels|instagram_feed|instagram_stories|threads|facebook|naver_blog|tiktok|x",
               "verdict": "lead|support|skip",
               "why_data": "<one sentence quoting evidence or statistics numbers>",
               "why_category": "<one sentence of industry reasoning, no numbers>",
               "how": "<one or two sentences: format, cadence, what the first post is>"}]}
```
`ValidateChannels`: enums; 3–6 channels; `why_data` numbers ⊂ allowed set (collected from
evidence + stats, as plain, percent and ×-forms); `why_category` and `how` through
`noNumbers`. Playbook prompt gains `{{CHANNELS_JSON}}`; playbooks regenerated.

### Spark role 8: translation (`prompts/translate.md`, cache `ko/<name>.json`)

One call per cache file: "translate every string value to natural Korean for a small brand
owner; keep keys, numbers, handles, hashtags, platform and brand names". `ValidateTranslation
(en, ko)` walks both: same keys, strings→strings (non-empty), non-strings equal; otherwise
the English value is kept. Server `GET /api/i18n/ko` flattens every (en string → ko string)
pair across cache files into one map.

### Server

- `POST /api/meta/connect {source: "mock"|"instagram", handle, token?}` → loads
  `data/meta/<handle>/` (mock) or fetches live (Instagram Graph API: `me/insights`,
  `me/media?fields=...,insights.metric(...)`; Threads API; Marketing API delivery_estimate);
  stores on the server; returns the evidence.
- `GET /api/evidence` → `{evidence, stats, channels}` (channels from cache, validated).
- `/api/directions` unchanged plus `channels` at the top level.
- `GET /api/i18n/ko` → map.
- Launch: `/api/launch` adds `reach` and `creators` (with fit labels from
  `creator-<username>.json` when cached).

### Web

- `web/i18n.js`: `KO` dictionary of static strings keyed by English; `t(s, vars)`;
  `tx(s)` for Spark text via the server map; `lang` in localStorage, default `en`; the header
  gets the toggle; after every render a `translateDOM()` pass swaps exact-match text nodes.
- Directions: Channels card above the direction cards.
- Setup: "Connect Instagram (demo data)" button + audience line.
- Launch: reach line on Ads; suggested creators list on Creators.
